# WhisperKey — AI interaction transcript (project record)

**Scope.** This document is the record of the AI interactions that produced the
WhisperKey submission (reverse-engineering, Trojan generation, insertion, testing,
and key recovery). It is organized chronologically by stage. Prompts are given in the
form they were asked; the AI's responses are summarized together with the concrete
artifacts (code, scripts, results) they produced, which are included in this repository.

**Model / access.** Claude (Anthropic) through a conversational session, driving a
scripted insert/test wrapper (`../tools/pipeline.py`). Per the challenge rule, **all
hardware — the Trojan and the exploit testbench — was generated by the AI**; no Verilog
was hand-written by a human. Unrelated messages from the broader chat session (not about
this project) are intentionally omitted.

## Stage 1 — Reverse engineer the accelerator

**Prompt:** "The source RTL isn't provided for this challenge — only a bitstream, the
interface doc (`ice40_cryptographic_IP.md`), the MicroPython driver, and block diagrams.
There is one known test vector: plaintext `0x59C359C3` → ciphertext `0x9CD84392` (encrypt).
Reconstruct a clean Verilog model of the design: the 32-bit SPI shift register (MSB-first,
with parallel load on readback), the round-controller FSM, and the cipher round. The
diagrams indicate 4 rounds, an AES S-box per byte, an 8-bit byte rotation, and a per-round
XOR with a fixed key K."

**AI response / output.** Produced `rtl/les_crypto_golden.v`: the SPI shift register, the
`data_word` latch, a 6-state round-controller FSM (`IDLE → S1..S4 → LD`, result parallel-
loaded in `LD` so `BUSY` falls at load), and the round function. Noted that one known
vector does not uniquely fix the round *structure*, so the exact ordering of the three
primitives (rotate / substitute / key-XOR), the rotate direction, and whether the forward
or inverse S-box is used must be determined by search.

---

## Stage 2 — Recover the cipher structure and key (bonus)

**Prompt:** "Since one vector doesn't pin the structure, brute-force it. For each candidate
round structure (S-box vs inverse S-box, ROTL8 vs ROTR8, operation order, key-XOR position),
test all 2³² keys against `0x59C359C3 → 0x9CD84392` and report which `(structure, key)`
reproduces the vector. Then cross-check the winner against the embedded key annotated in
the provided block diagrams."

**AI response / output.** Wrote `tools/key_recovery.c` (self-contained AES S-box, brute
force over all 2³² keys). The search converges **uniquely** on:

```
round:  x_{i+1} = SBox( ROTL8( x_i XOR K ) ),   4 rounds,   ciphertext = x_4
key:    K = 0x8E043CB1
```

This key reproduces the test vector exactly and **matches the value `K = 0x8E043CB1`
annotated in the provided encryption/decryption diagrams** (`docs/les_block_diagrams`),
confirming the recovery independently. Decryption is the exact inverse,
`y_{i+1} = ROTR8( InvSBox(y_i) ) XOR K`.

**Correction captured in the log.** An earlier pass had matched the single test vector with
a different `(structure, key)` pair (`InvSBox(ROTL8(x⊕K))`, `K=0x5FB31A52`) — a genuine
*alias* that reproduces one vector but is not the real cipher. Cross-checking against the
provided diagrams exposed the alias; the structure and key were corrected to the values
above, and all files and simulations were updated accordingly. (This back-and-forth is
part of the honest record.)

## Stage 3 — Generate the WhisperKey Trojan

**Prompt:** "Using the golden RTL, design a stealthy key-exfiltration hardware Trojan.
Requirements: (1) a rare, exact-match trigger on the latched input word; (2) a payload that
leaks the key over the existing MISO output, not a new port; (3) normal operation stays
bit-for-bit identical when not triggered; (4) minimal area; (5) one-shot so it auto-disarms.
Output only the Verilog for the trigger logic and the output mux."

**AI response / output (the inserted Trojan core):**

```verilog
reg armed;
always @(posedge SCK) begin
    if (!RST_N)                               armed <= 1'b0;
    else if (START && (data_word == TRIGGER)) armed <= 1'b1;  // trigger match
    else if (load_output)                     armed <= 1'b0;  // one-shot
end
wire [31:0] load_value = armed ? SECRET_KEY : result;         // payload mux
```

Trigger = exact word `0x1337C0DE` (false-fire probability 2⁻³²). Payload steers the
shift register's parallel-load input to the key register, so the key shifts out over MISO
on the next readback. Classification: conditional, externally-triggered, information-leakage
Trojan at RTL.

## Stage 4 — Automate the insertion (two techniques)

**Prompt:** "Write a pipeline that inserts this Trojan into the golden RTL automatically —
no hand-editing the trojaned file. Rename the module, add the TRIGGER parameter, route the
shift-register parallel load through the mux, and splice the Trojan block at a named anchor.
Then also do it a second, more advanced way: at the AST level with pyverilog."

**AI response / output.**
- `tools/pipeline.py` — one-command generate → insert (structural text at named anchors)
  → compile → simulate → report.
- `tools/ast_insert.py` — parses the golden RTL into a Verilog AST (pyverilog), grafts the
  Trojan nodes, rewrites the output-load statement's RHS `result → load_value` at the AST
  level, and regenerates `rtl/les_crypto_trojan_ast.v`. This is the "advanced technique
  (AST manipulation)" insertion path.

---

## Stage 5 — Exploit testbench and stealth proof

**Prompt:** "Write a testbench that (A) checks the trojaned chip still matches the known
vector, (B) runs the golden and trojaned chips in parallel on a batch of ordinary inputs
and asserts their outputs are bit-identical (stealth), and (C) sends the trigger and checks
the key appears on MISO. Also render a waveform of the leak, and report synthesized area
overhead with Yosys."

**AI response / output.** `tb/tb_exploit.v` (checks A/B/C), `tb/tb_wave.v` +
`tools/render_waveform.py` (timing diagram of the key leak), and `tools/area_report.py`
(Yosys golden-vs-trojan area). A timing bug (parallel-load one cycle early) and a testbench
MISO-readback bug were found via failing simulations and fixed in the loop.

**Final automated result (`python3 tools/pipeline.py`):**
```
[A] vector 0x59C359C3 -> trojan out 0x9CD84392 : PASS
[B] stealth - trojaned vs clean chip on 8 ordinary inputs : all identical
[C] exploit - trigger 0x1337C0DE -> KEY LEAKED over MISO: 0x8E043CB1
    result: ALL CHECKS PASSED (0 failures)
```

Synthesized overhead (Yosys): +159 cells (+3.9%) — a small fraction of the design.
